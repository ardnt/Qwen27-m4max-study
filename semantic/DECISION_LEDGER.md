# Decisions revisited

This ledger covers the available local source, screening experiments, and cited public work. Private engineering discussions and every abandoned idea across all inference projects are not observable. Historical screens below were recomputed from existing records; they were not rerun.

| Decision or approach | Earlier reason or evidence | What changed or remains limiting | Action |
|---|---|---|---|
| Require 2,048 tokens of junction gain | `Engine.cpp` tied the minimum gain to one draft window, pricing a snapshot, command split and up to a complete window | Adjacent complete draft states continue. For short gaps, splitting a window can add **zero** draft rows. Actual snapshots cost a few to tens of ms, while a miss can cost seconds | Replace the optional anchor threshold with measured expected-cost selection |
| Lazy junction discovery | KV identity could reveal a shared prefix after the first branch, but a recurrent state at that prefix did not necessarily exist | A structural user-turn boundary predicts a likely branch before it happens | Admit a checkpoint on the first request when its expected savings exceed capture/split cost |
| Keep only the latest turn anchor | Reduces state storage and handles common final-user edits | Earlier edits can diverge before that anchor; each full snapshot is 187 MiB here | Offer several turn boundaries; choose at most two per decision under a 512 MiB additional-state budget; global retention remains native |
| Score each checkpoint independently | Easy greedy rule | Two nested points can both claim the same avoided work; an additional split can make the sum worse | Joint shortest-path selection charges each overlap to its deepest retained predecessor once |
| Learn reuse from cache hits | Runtime exposes hit counters | Missing checkpoints suppress the hits that would have justified them | Learn from exact successive request-token overlap, including misses, independently of placement |
| Train by the new request's shape | Separates long system prefixes from short system/long user messages | Editing an older turn can turn a multi-turn request into one turn, misattributing its outcome | Attribute each transition to the previous prompt's shape; test the cross-shape case |
| Treat prefill as one throughput rate | Convenient throughput scalar | This engine dispatches up to **2,048** rows. ANE starts at **512** rows, register prefill ends at **128**. Middle tails follow a different route | Learn separate bulk/middle/short cost bands, draft-row contribution and command intercept |
| Always take the deepest semantic point | Minimizes replay rows | Splitting a 1,152-row bulk into 512 + 448 + 192 can create two expensive GPU tails. One earlier checkpoint can have better expected total cost | Offer aligned alternatives and optimize current capture plus future reuse jointly. Live multi-turn experiments adapted from 960 to 512 |
| Keep periodic recovery only | Limits persistent state and allows suspension/recovery | Rolling points may be retired before the sibling request arrives | Preserve required recovery/replay/shared-peer captures; separately select ordinary retained states |
| Smaller DFlash windows, 256/512 | Potentially cheaper attention/context handling | Existing 3-sample English screens: full-window control 33.37 tok/s, recent256 32.07, recent512 31.75. No convincing consistent gain; target verification alone does not prove unchanged proposal quality | Preserve the full 2,048-token ring; price its actual materialization work instead |
| Unary draft selector | Could lower launch work | Existing English median 34.78 → 33.98 tok/s; Arabic 26.88 → 25.40, n=3 each | Leave disabled; checkpoint placement does not supply new evidence for enabling it |
| Target K-split groups 4/8 | More parallel reduction | Existing groups4 English median 33.26 vs 34.78 control; groups8 34.99, n=3. Small gains are confounded/noisy | Preserve qualified default. Revisit only with a changed kernel/hardware cost profile |
| Early fused register FFN | Fewer graph operations | Earlier version rounded the up projection to BF16 before SiLU, changing the qualified numerical path | Preserve the qualified original FP32 epilogue; performance does not resolve the numerical objection |
| Disable ANE validation or rely on a failed calibration | Avoid startup work | A prior isolated calibration failure distorted an 8K timing. A faster invalid path is not a valid improvement | Preserve cached calibration validation, numerical checks and the native fallback/breaker |
| Approximate recurrent state from a recent suffix | Avoid full snapshots at arbitrary page boundaries | [SuffixReplay](https://arxiv.org/abs/2609.33477) explicitly reconstructs an approximate state. Its quality results are workload/model dependent | Research alternative, not installed in this exact-state planner |
| Semantic embeddings authorize similar-prefix reuse | Could increase hits for paraphrases | Different tokens or images require different target recurrent/KV state | Structural semantics guide placement only; native token/image identity still authorizes reuse |
| Snapshot after every generated reply | Could remove replay of previous assistant output | `finish()` releases the lane. Decode can emit a terminal token without KV, and a desired page boundary may lie inside a committed verify block. Full draft/target state at the same boundary must be proven | Deferred. Need an explicit verified composite-state availability contract before adding decode checkpoints |
| Save every point and let LRU decide | Simpler aggressive admission | Each snapshot is large; new entries can evict valuable unrelated histories | Two-state/byte cap plus growth-pause abstention; native admission, leases and eviction remain authoritative. Global eviction opportunity cost is not learned yet |

## What is distinctive in this implementation

The useful contribution is the integration: a small bounded host planner whose edge cost includes the existing DFlash2 continuation/reset geometry, mandatory recovery captures, actual prefill route thresholds, measured snapshot/restore wall time and miss-independent reuse observations. It has a reviewable cost receipt and a reversible native switch. The measured improvement is fewer redundant target and draft prefill rows on branches.

This is not a claim to invent sparse checkpoint optimization. [Marconi](https://arxiv.org/abs/2411.19379) already combines hybrid cache admission/eviction with reuse forecasts and compute/memory value. [Sparse Prefix Caching for Hybrid and Recurrent LLM Serving](https://arxiv.org/abs/2605.05219) formalizes overlap-distribution checkpoint placement and gives an exact dynamic program. Our bounded cost extension addresses this specific Splash/DFlash2 host path; superiority over those systems is untested.

## The next concrete seam

The 129–511-row region remains a useful kernel target. A 198-row changed suffix still takes about 1.2 seconds even after its 1,024-token prefix is restored. The planner exposes that route cliff and can sometimes prefer an earlier anchor that leaves an ANE-sized replay. A dedicated middle-sized prefill optimization would need its own numerical checks and paired latency test. No such kernel speedup is claimed here.
